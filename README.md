# UA RTL Audit

A smart, lightweight Chrome extension (Manifest V3) for RTL readiness:
**one keystroke flips any page to `dir="rtl"` and audits it for direction
bugs** — viewport overflow, clipped elements, truncated text, physical
alignment, unmirrored inputs, and icons that probably need mirroring —
with an in-page panel you can click through and a markdown report ready
for a ticket.

No dependencies, no build step, ~25 KB of plain JS.

## Install (unpacked)

1. Open `chrome://extensions`
2. Enable **Developer mode** (top right)
3. Click **Load unpacked** and select this folder (`ua-rtl-audit`)

## Use

- **Alt+Shift+R** anywhere, toolbar button, or right-click → *Flip direction (LTR ↔ RTL)*
- The tab shows an **RTL** badge while flipped; any navigation clears it (the flip is per page load)
- **Run audit** (popup or context menu) → findings panel appears bottom-right
- Click a finding → the element scrolls into view and flashes amber
- **Copy report** (panel or popup) → markdown ready to paste into a ticket
- Optional: *Also set `lang="ar"`* while flipped (popup toggle) to test font/shaping fallbacks too
- **Restore LTR** returns the page's exact original `dir`/`lang` attributes

## What the audit checks

| Check | Severity | Catches |
|---|---|---|
| `viewport-overflow` | error | document wider than the viewport under RTL |
| `clipped` | error | elements crossing a viewport edge (skipped when the document itself overflows — that'd be noise) |
| `truncated` | warn | text clipped by `overflow: hidden` / ellipsis — real data-loss risk in RTL layouts |
| `dir-input` | warn | `input[type=number/tel/email/url]` without an explicit `dir` — digits and latin fragments render mirrored |
| `physical-align` | info | `text-align: left/right` instead of logical `start/end` |
| `icon-naming` | info | elements named `arrow`/`chevron`/`next`/`back`… — candidates for mirroring |

Tolerances (2px) keep sub-pixel rounding and hairline borders out of the
report. Info-level checks are capped at 25 findings each with a "+N more"
note. The audit walks at most 2000 visible elements.

## What makes it careful

1. **Exact restore** — the original `dir`/`lang` attribute *values* are
   remembered (including "absent"), so restoring never invents attributes.
2. **Shadow-DOM panel** — the findings UI lives in a shadow root with
   `all: initial`, so it can't collide with or leak into the page's CSS.
3. **Pure predicates** — every check is a plain-data function
   (`shared/rtlcore.js`, no DOM), unit-tested in Node; the content script
   only collects facts.
4. **Idempotent injection** — the bundle re-injects safely on every action;
   nothing accumulates.
5. **Permission footprint** — `activeTab` + `scripting` only; the extension
   never runs on a page until you act on it.

## Structure

```
manifest.json          MV3 manifest (activeTab + scripting + storage + contextMenus)
background.js          service worker: command/context menu/popup wiring, RTL badge
shared/rtlcore.js      pure audit predicates + report builder (dual-format module)
shared/inject.js       content-bundle injection helper
content/rtl.js         flip state machine, fact collection, shadow-DOM panel
popup/                 flip / audit / report UI
icons/                 generated by tools/gen-icons.js
```

## Verify

```
node test/run-tests.js                       # unit tests (all predicates + report)
NODE_PATH=… node test/e2e.js                 # real-Chrome e2e (see header comment)
node tools/gen-icons.js                      # regenerate icons
NODE_PATH=… node tools/make-screenshot.js    # regenerate the store screenshot
```

The e2e suite loads `test/demo-rtl.html` — one planted defect per check —
and asserts every check fires, restore is exact, the panel renders, and
20 rapid toggles stay consistent.

## Notes & limits

- The flip changes presentation only; pages that hardcode direction in JavaScript may need a reload while flipped.
- `physical-align` and `icon-naming` are heuristics (info severity) — a right-aligned price may be intentional; use judgment.
- Cross-origin iframes aren't audited (injection is top-frame only, matching the minimal permission model).
- `text-align` computed values depend on the page's own CSS cascade; logical `start`/`end` values are never flagged.
